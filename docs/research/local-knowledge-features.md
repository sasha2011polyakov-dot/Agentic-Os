# Возможности для работы с локальной информацией

Дата: 2026-10-12. Источники — см. `product-landscape.md`. Для каждой гипотезы ниже: что работает **обычным кодом**, где **действительно нужна модель**, и итоговое решение.

## A. Интеллектуальный поиск

## B. Интеллектуальная обработка документов

| Операция | Кодом | Нужна модель |
|---|---|---|
| Тип документа | Frontmatter `type`, расширение, путь (`docs/`, `adr/`, `test/`) | Классификация свободных заметок без метаданных |
| Заголовки, структура, оглавление | Парсер Markdown | — |
| Сущности и терминология | Заголовки, жирный текст, глоссарии, ключи frontmatter | Именованные сущности в свободном тексте |
| Требования | Шаблоны «должен/должна/shall/must», ID вида `REQ-…` | Атомизация, нормализация, критерии приёмки |
| Ключевые решения | Документы `type: decision`/ADR | Извлечение решений из протоколов встреч |
| Незакрытые вопросы | Строки с `?` в разделах «Вопросы»/«Open questions», незакрытые `- [ ]` | Неявные вопросы |
| Сравнение версий | Построчный diff (LCS) | Смысловой diff |
| Устаревшие сведения | Даты, срок проверки источника, ссылки на заменённые документы (`supersedes`) | Смысловое противоречие с новой версией |
| Резюме | — | Да |

**Принцип:** всё, что надёжно делается кодом, делается кодом: это бесплатно, воспроизводимо и работает офлайн.

## C. Автоматическое связывание знаний

1. **Явные связи** (из ссылок, frontmatter `project`, `depends_on`, `implements`, `supersedes`, `conflicts_with`) → `origin = explicit`.
2. **Извлечённые детерминированно** (файл в папке проекта → `belongs_to`; задача создана из требования → `derived_from`) → `origin = extracted`.
3. **Предложенные ИИ или по сходству** (эмбеддинги, совпадения терминов) → `origin = ai_suggested`, `status = suggested`, обязательны `confidence` и `evidence` (на чём основано). В графе отображаются пунктиром и скрываются фильтром по умолчанию. Пользователь принимает их (→ `confirmed`) или отклоняет (→ `rejected`; повторно не предлагаются).

## D. Анализ проектов и репозиториев

- **Карта проекта (v1, кодом):** дерево с учётом `.gitignore` и правил исключения; языки по расширениям; манифесты (`package.json`, `pyproject.toml`, `requirements.txt`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle`, `composer.json`, `Gemfile`); точки входа (`main`/`bin` из манифестов, `src/main.*`, `index.*`, `app.*`); тесты (`test/`, `tests/`, `*_test.*`, `*.test.*`, `*.spec.*`); документация (`README*`, `docs/`, `*.md`, ADR).
- **Outline символов (v1, regex):** TS/JS (`export function|class|const`), Python (`def`, `class`), Go (`func`, `type`), Rust (`fn`, `struct`, `enum`, `trait`), Java/Kotlin/C# (`class`, методы с модификаторами доступа). **Ограничение:** regex не понимает вложенность и макросы; утверждать «код проанализирован полностью» запрещено.
- **Git (только чтение):** ветка и HEAD читаются напрямую из файлов `.git` (без запуска процесса); `git log`/`status` — опционально, с защитными флагами (см. `docs/architecture/security.md`, раздел про Git).
- **Связь требований с кодом:** упоминания ID требований (`REQ-001`) в коде и тестах → рёбра `implements`/`verifies` (`origin = extracted`).

## E. Управление знаниями во времени

- Каждый документ: `created`/`updated` из frontmatter (если есть) и из ФС; история версий в БД.
- Каждый факт из веба: `published_at` (если известна) отдельно от `retrieved_at`; `verified_at` и `review_after` (срок повторной проверки).
- **Устаревание без удаления:** документ получает вычисляемый статус `stale`, если истёк его `review_after` или если есть ребро `superseded_by`. Устаревший документ остаётся в базе, в UI получает пометку и попадает в отчёт «Требуют проверки».
- Задачи, зависящие от требований со статусом `superseded`/`stale`, подсвечиваются.

## F. Автоматизация повседневной работы — оценка

| Сценарий | Польза | Стоимость | Риск ошибочной автоматизации | Решение |
|---|---|---|---|---|
| Проверка ссылок и целостности базы | Высокая | Нулевая (код) | Нет | **v1**: отчёт целостности |
| Сводка изменений за день/неделю | Высокая | Код (список изменений) + опционально модель (резюме) | Низкий: только чтение | **v1**: детерминированный список на Главной; ИИ-резюме — расширенная функция |
| Незавершённые задачи | Высокая | Код | Нет | **v1** |
| Заметка по результатам исследования | Высокая | Модель | Средний → ревьюер + подтверждение пользователя перед сохранением | **v1** |
| Подготовка ТЗ из материалов | Очень высокая | Модель, много вызовов | Высокий → мультиагентный конвейер с валидацией и подтверждениями | **v1** |
| Поиск потерянных договорённостей | Средняя | Модель по протоколам встреч | Средний | Расширенная функция: агент по выбранным документам |
| Обновление документации после изменения кода | Средняя | Модель | **Высокий**: запись в файлы | Только предложение diff, применение — вручную; позже |
| Отчёт о состоянии проекта | Средняя | Код (задачи, статусы) + модель | Низкий | Расширенная функция |
